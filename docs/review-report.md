## 审查结论

应优先修复三处会影响部署结果或保存能力的问题。同一环境能够并发启动两次，上传替换失败可能让原目标路径失去文件，一次写盘失败会让后续保存持续失败。SSH 指纹更新和上传空闲超时也应纳入本轮修复。

- **P1** 会破坏执行互斥、影响远端文件或信任状态、阻断持续写入，或让任务长期占用执行资源。
- **P2** 影响常用功能、历史数据完整性或 IPC 文件访问边界。

## P1 问题

### 1. 同一环境可同时启动两次

两个启动请求可以同时通过环境锁检查。代码在检查之后异步生成上传计划并读取密码，直到建立运行上下文后才加锁。两个任务可能并行传输文件或执行同一环境的命令。先结束的任务还会按环境 ID 释放共享的锁，剩余任务继续运行时可能接受第三次启动。 [锁检查](../src/main/services/runner.ts#L152) · [异步预检与凭据读取](../src/main/services/runner.ts#L162) · [加锁](../src/main/services/runner.ts#L215) · [释放锁](../src/main/services/runner.ts#L616)

本地模拟同时发出两个启动请求，两次均获准，假 SSH 连接收到两次调用。现有互斥用例在首次启动返回后才发出第二次请求，遗漏了加锁前的异步窗口。 [现有互斥用例](../src/main/services/runner.test.ts#L408)

在第一次异步操作前占用环境锁，按运行归属释放，并处理预检、凭据读取和入队落盘失败。回归用例应同时发出两个请求，确认只创建一条运行记录并尝试一次 SSH 连接。启动校验或落盘失败后，同一环境应可以再次启动。

### 2. 备份完成后替换失败会使原目标路径缺少文件

备份策略先把旧文件移到备份路径，再安装已上传的临时文件。如果第二步失败，异常处理仅清理临时文件，旧文件留在备份路径。依赖原目标路径的服务可能因此中断。 [替换逻辑](../src/main/services/upload.ts#L243) · [异常清理](../src/main/services/upload.ts#L104)

假远端执行器模拟原文件已备份、安装新文件失败。应用报告上传失败并执行临时文件清理，旧文件没有恢复到原路径。现有测试覆盖备份成功路径。 [现有备份用例](../src/main/services/upload.test.ts#L139)

让备份和替换具有明确的失败恢复行为，优先保留旧目标，或在可安全恢复时将旧文件移回原位。恢复失败时记录目标路径、备份路径和失败阶段。回归用例应模拟备份成功后替换失败，确认原路径保留旧文件，或在恢复受阻时报告可定位的恢复信息，并确认后续部署命令未启动。

### 3. 一次写盘失败会阻断后续保存

`StoreService.flush()` 将每次写入接到同一条 Promise 链上。原子写失败后，链保留拒绝状态，此后的保存请求直接继承失败。即使磁盘或目录恢复，当前进程仍无法保存后续配置和运行状态。 [保存调度与写入队列](../src/main/services/store.ts#L82) · [原子写入](../src/main/utils/atomicFile.ts#L8)

模拟第一次文件重命名报错、后续重命名可成功。第二次调用 `flush()` 仍返回首次错误，模拟文件系统总共只收到一次重命名。

向本次调用方返回写入错误，同时让队列继续接收后续写入，并处理防抖保存的失败。回归用例应确认首次失败能被观察到，后续保存成功落盘，并发保存后磁盘内容对应最近一次提交的状态。

### 4. 更改服务器地址时会删除新地址的 SSH 指纹记录

更新逻辑先比较旧地址与输入，随后原地修改服务器对象，最后从同一个对象读取地址来删除指纹。因此删除参数已经是新地址。若新地址已有信任记录，连接时会重新发起首次信任确认，旧地址的记录仍在。信任记录按主机与端口共享，这也可能影响指向新地址的其他服务器配置。 [地址更新与指纹清理](../src/main/ipc/server.ts#L42) · [指纹查找](../src/main/services/knownHosts.ts#L29) · [首次信任确认](../src/main/services/ssh.ts#L135)

更新前保存旧主机与端口，按旧地址及其现有引用处理信任记录。回归用例应确认更改地址或端口后，新地址原有的信任记录仍然有效，并验证旧地址仍被其他配置引用时的行为。

### 5. SFTP 上传空闲超时只覆盖文件传输

空闲计时器只在 `fastPut` 内运行。打开 SFTP、创建远端目录、读取文件元数据、远端替换及失败清理分别等待各自的回调，缺少应用层截止时间。SSH 连接仍存活但某个回调迟迟不返回时，任务可能长期停在上传状态并占用执行资源。 [打开 SFTP](../src/main/services/runner.ts#L397) · [创建目录与校验大小](../src/main/services/upload.ts#L43) · [传输计时器](../src/main/services/upload.ts#L119) · [远端替换与清理](../src/main/services/upload.ts#L263)

本地假 SFTP 在文件传输成功后让大小校验一直等待，超过监测周期后上传仍未结束。设计文档要求在无字节进度达到空闲阈值时终止上传。 [设计文档的上传超时](../docs/design.md#L457)

为各上传阶段设置可结束等待的超时和取消处理，失败清理也应有截止时间。分别模拟打开 SFTP、查询元数据和远端替换无响应，检查任务进入预期终态并释放环境锁和并发名额。持续收到字节进度的大文件上传应能继续。

## P2 问题

### 6. 填写密码后，服务器抽屉的测试连接会校验失败

「测试连接」只从表单取地址、端口、账号和密码。填写密码时，IPC 将这组值当作临时服务器配置校验，复用的新增服务器 schema 要求名称。即使用户在抽屉里填了名称，测试请求也缺少该字段，因此在连接前被拒绝。使用实际表单组件和 IPC schema 检查时，失败项是 `input.name`。 [抽屉取值与请求](../src/renderer/src/pages/servers/ServerDrawer.tsx#L44) · [必填名称](../src/shared/schema.ts#L12) · [测试参数校验](../src/shared/schema.ts#L269)

让表单提交字段与临时连接 schema 一致。新增服务器、编辑时输入新密码、编辑时使用已保存密码三条路径都应通过参数校验并到达连接测试入口。

### 7. 历史日志分页会静默丢弃长记录

日志分页按字节读取。当单条序列化后的 JSONL 记录超过一页，读取器可能得到半条记录。解析失败后当前逻辑丢弃片段并推进偏移，后续页面无法补回内容。本地检查写入三条各含 65,536 个控制字符的记录，累计分页返回了 0 个字符。现有分页用例使用短记录。 [分页实现](../src/main/services/logStore.ts#L86) · [现有分页用例](../src/main/services/logStore.test.ts#L34)

让分页游标与完整记录的边界一致，按明确的上限处理跨页记录。回归用例应覆盖 JSON 转义、多字节字符及单条记录跨多个页面，并确认分页拼接结果与原始内容一致，游标持续推进且记录不重复。

### 8. 日志 IPC 缺少文件范围校验

读取和删除日志的接口接受任意非空运行 ID，日志服务直接用 ID 构造文件路径。主进程没有在这两个入口同时验证运行记录归属和文件路径范围。 [运行 ID 校验](../src/shared/schema.ts#L313) · [日志读取入口](../src/main/ipc/run.ts#L33) · [日志删除入口](../src/main/ipc/run.ts#L52) · [路径构造](../src/main/services/logStore.ts#L65)

按可信运行记录定位日志，并在日志服务中验证解析后的文件路径位于日志目录内。覆盖有效记录、无对应记录及无效 ID 的处理，确认读取、删除与导出遵循同一文件范围约束。
